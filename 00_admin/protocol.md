# Протокол огляду літератури

Версія 0.1 — <!-- РРРР-ММ-ДД --> (див. журнал змін, розд. 11). Конфіг для скілів `litnote-collect` (Stage 1) і `litnote-summarize` (Stage 2).

Призначення: зафіксувати **до** масового збору, що саме шукаємо, що беремо і що відкидаємо. Без цього обсяг бібліотеки не є аргументом на захисті, бо критерій відбору лишається неявним і не відтворюваним.

> [!tip] Як заповнити
> Скажіть Claude «налаштуй сховище» (скіл `vault-setup`) — він складе чернетку розділів 1–4 і 6 за вашою темою з `config.md`. Чернетку потрібно переглянути: RQ — це ваші рішення, а не Claude.
> Розділи 5, 7, 8, 10 уже заповнені загальними правилами — міняйте, лише якщо є причина, і записуйте зміну в розд. 11.

## 3. Критерії включення

Джерело береться, якщо виконано **всі** пункти.

| Код | Критерій |
|---|---|
| **I1** | Відповідає щонайменше одному RQ і робить це основним предметом, а не згадкою у вступі. |
| **I2** | Рецензоване видання, матеріали конференції або звіт зі змагання (shared task). Препринт — лише якщо це єдина версія значущої роботи або має ≥50 цитувань. |
| **I3** | Рік видання <!-- 2016 --> і новіший. Виняток — канонічні роботи, на які спирається сучасний стан; позначаються тегом `canonical`. |
| **I4** | Мова публікації — <!-- англійська або українська -->. |
| **I5** | Містить **або** емпіричну оцінку з метриками, **або** опис ресурсу (корпус, схема розмітки, лексикон), **або** систематичний огляд із таблицею порівняння. |
| **I6** | Доступний повний текст. Без повного тексту — статус `abstract-only`, **не входить до ядра**, числа не цитуються. |

## 4. Критерії виключення

Достатньо **одного** пункту, щоб відкинути.

| Код | Критерій |
|---|---|
| **E1** | Немає ні метрик, ні описаного ресурсу: публіцистика, есе, огляд без порівняльних даних, анонси. Огляд старший за ~3 роки в підгалузі, що швидко змінюється, — лише точка входу для snowballing, не «state of the art». |
| **E2** | Не є статтею: збережена сторінка ResearchGate чи Academia.edu, лендінг видавця, презентація. Ознаки — назва починається з `(PDF)`, видавець = ResearchGate, немає автора. |
| **E3** | <!-- поза межами за модальністю / даними, напр. «основний внесок мультимодальний» --> |
| **E4** | <!-- поза межами за предметом --> |
| **E5** | Задача суміжна, але інша: <!-- перелік --> |
| **E6** | Дублікат або попередня версія роботи, вже наявної в бібліотеці. Лишається остання/повніша версія. |
| **E7** | Ознаки хижацького видання або відсутність рецензування при заявленому статусі журналу. |

**Правило граничного випадку.** Якщо рішення не очевидне — `maybe`, відкладається; розглядається лише тоді, коли квота відповідного RQ не набрана. Час на суперечку про одне джерело дорожчий за саме джерело.

## 5. Джерела пошуку

| Канал | Роль | Обмеження |
|---|---|---|
| Consensus (MCP) | основний генератор кандидатів | 10 результатів на запит, DOI не повертає |
| arXiv через `WebSearch` з `allowed_domains: ["arxiv.org"]` | другий генератор кандидатів: препринти й авторські версії воркшопів, яких Consensus не бачить | програмний API `export.arxiv.org` заборонений robots.txt; сторінки `abs/` при частих зверненнях дають 429 |
| Веб-пошук за точною назвою | DOI зі сторінки видавця | по одному кандидату за раз |
| OpenAlex за DOI | метадані, `oa_url`, `referenced_works` для snowballing | лише шлях `works/doi:...`; URL із query-параметрами — 429 |
| Scopus / Web of Science | булеві запити розд. 6.1; контроль повноти | **ручний канал, виконує автор** (доступ через мережу університету); експорт у Zotero лише після скринінгу |
| Google Scholar | вперед-snowballing («Цитується»), пошук запитами мовою роботи | ручний канал |
| Zenodo, Hugging Face Datasets | корпуси: картка, ліцензія, версія | корпус без статті сам по собі не проходить I5 |
| DOAJ | фільтр для E7 | не канал пошуку |
| <!-- національні журнали, архів університету --> | <!-- --> | <!-- --> |

**Правило версії.** Якщо існує опублікована версія — брати її, а не препринт: сторінки не збігаються, а якорі нотаток прив'язані до сторінок.

**Snowballing.** Для кожного джерела з `relevance: High` — `referenced_works` з OpenAlex (назад) і «хто цитує» (вперед, Google Scholar).

## 7. Процедура скринінгу

**Крок 0 — назва й абстракт.** Кандидат оцінюється за I* та E* без відкривання повного тексту. Рішення — рядком у `90_pipeline/out/screening.md`: назва, рік, RQ, рішення (`include` / `exclude` / `maybe`), код причини, канал. Цей журнал і є доказом відтворюваності відбору.

**Крок 1 — DOI й Zotero.** Лише для `include`. Порядок за скілом `litnote-collect`.

**Крок 2 — повний текст.** Стаття виявилась про інше → запис видаляється з Zotero, у журналі `exclude` з поміткою «після повного тексту». Немає повного тексту → по черзі: «Знайти доступний PDF» у Zotero → Unpaywall за DOI → авторська версія → бази університету → `abstract-only`.

**Крок 3 — нотатка.** Stage 2, скіл `litnote-summarize`, статус `summarized`.

**Крок 4 — верифікація.** Тільки людина: звірити числа з PDF, поставити `verified_by_human: true`. Чернетка тексту може спиратися на неверифіковані нотатки; перед поданням розділу всі його джерела проходять верифікацію.

## 8. Точка насичення

Збір по конкретному RQ припиняється, коли **три поспіль** нові джерела не додають нічого з переліку:

- нового методу або постановки задачі;
- нового корпусу чи схеми розмітки;
- числа, що змінює калібрувальні факти в `00_admin/facts.md`;
- суперечності з уже зафіксованим висновком.

Лічильник ведеться **окремо для кожного каналу**: новий канал починає з нуля.
