# Налаштування сховища з шаблону

Перетворює чистий шаблон на сховище конкретної роботи — диплома, статті, курсової, PhD чи власного дослідження. Після цього скіла працюють `litnote-collect` → `litnote-summarize` → `litnote-maintain` і `vault-git`.

## Залізне правило

**Особисте пишеться лише в `00_admin/config.md`** (і в похідні, перелічені нижче: `protocol.md`, `PROJECT_PROMPT.md`, `70_writing/title.md`, рядок мови в `_matrix.md`). `CLAUDE.md` і скіли не редагувати — вони спільні для всіх, хто користується шаблоном, і читають config самі.

**RQ і критерії — рішення автора, не Claude.** Протокол заповнюється як **чернетка** зі статусом 0.1; версією 1.0 він стає лише після того, як автор переглянув і погодив.

## Процедура

### 1. Знайти сховище й перевірити стан

- Сховище — підключена папка, у корені якої є `CLAUDE.md` і `00_admin/config.md`. Якщо підключено кілька папок — спитати, яка з них.
- Прочитати `config.md`. Заповнені поля не перепитувати — лише підтвердити одним рядком.
- Файли на комп'ютері користувача редагувати **на місці** (`device_bash` + короткий python read-modify-write), а не переписувати з пам'яті.

### 2. Розпитати

Не більше **двох раундів** питань (інструмент запитань із варіантами, якщо є; інакше — один нумерований список у чаті). Порядок:

**Раунд 1 — обов'язкове:**

1. Тип роботи (`work_type`): магістерська, бакалаврська, PhD, стаття, курсова, звіт, власне дослідження.
2. Тема (повна назва) і 3–7 слів скорочено.
3. Лише для академічних робіт: заклад, кафедра, спеціальність, керівник. Для статті чи власного дослідження — пропустити.
4. Дедлайни: основна робота, супутня стаття (якщо є).
5. Мова даних, на якій фокус (`focus_language`), і предметна галузь одним рядком.
6. 3–6 речень про задум: що будується / досліджується, на яких даних, у чому новизна.

**Раунд 2 — середовище (можна вивести самому, а не питати):**

7. `vault_path` — шлях до цієї папки на комп'ютері (видно з підключених папок).
8. `zotero_storage` — зазвичай `C:\Users\<ім'я>\Zotero\storage` (Windows) або `~/Zotero/storage` (macOS). Якщо Zotero-папка підключена до сесії — взяти звідти. Інакше спитати.
9. `git_remote` — є репозиторій на GitHub чи ні.
10. Особливі домовленості, якщо є (мови джерел, які не цитуються, жорсткі вимоги кафедри).

Якщо відповідь «не знаю» — лишити поле порожнім і внести в перелік «що лишилось» у звіті. Не вигадувати.

### 3. Заповнити `00_admin/config.md`

Front matter — значення з відповідей; тіло — «Короткий опис задуму» і «Особливі домовленості». Перевірити, що YAML парситься (`python -c "import yaml,sys; yaml.safe_load(open('00_admin/config.md',encoding='utf-8').read().split('---')[1])"`). Шляхи Windows — в одинарних лапках.

### 4. Похідні файли

1. **`10_literature/_matrix.md`, розд. 5** — замінити `"uk"` у рядку `WHERE contains(string(language), "uk")` на `focus_language`.
2. **`70_writing/title.md`** — лише для робіт із титульною сторінкою за ДСТУ: заповнити відомі поля (університет, кафедра, тема, виконавець, керівник, місто й рік).
3. **`PROJECT_PROMPT.md`** — замінити всі `{{...}}` значеннями з config. Технічні поради в розділі «Технічна сторона» підібрати під галузь (моделі, методи, специфіку мови фокусу) — 3–6 пунктів, лише те, у чому впевнений; сумнівне не писати.
4. **`00_admin/state.md`** — дата, «Остання дія: налаштування з шаблону», наступний крок (зазвичай — погодити протокол).

### 5. Чернетка протоколу `00_admin/protocol.md`

Заповнити розділи 1–4 і 6, решту не чіпати:

- **Розд. 1** — мета огляду одним реченням; 3–5 пунктів «у межах», 3–5 «поза межами».
- **Розд. 2** — 3–6 RQ. Кожне — перевірювана теза, прив'язана до розділу роботи. Якщо в `00_admin/requirements/` є вимоги до структури (кафедри, журналу, конференції) — номери розділів брати звідти; якщо немає — писати «розд. ?» і згадати це у звіті. Квоти — орієнтовно 6–12 на RQ.
- **Розд. 3–4** — I3 (рік), I4 (мови), E3–E5 (що поза межами саме цієї теми). Решта кодів загальні — лишити.
- **Розд. 6** — 4–6 вузьких англомовних запитів на RQ (формула: задача + домен + метод/мова); по одному булевому запиту Scopus на RQ; 2–4 запити мовою роботи.
- **Розд. 11** — рядок `0.1 | <дата> | Чернетка з vault-setup | очікує погодження автором`.

Перед записом показати автору RQ (лише таблицю розд. 2) і спитати «погоджуєте чи правимо?». Це єдине місце, де варто зупинитись і чекати.

### 6. Перевірити інструменти

Через `device_bash` (на комп'ютері користувача), кожне одним рядком «є / немає → що зробити»:

| Що | Перевірка | Якщо немає |
|---|---|---|
| Python 3 + pyyaml | `python3 -c "import yaml"` | `pip install pyyaml` |
| pdftotext (poppler) | `which pdftotext` | Stage 2 читатиме PDF у хмарі — працює, але повільніше |
| git | `git --version` | встановити Git for Windows |
| Автоекспорт BBT | чи існує `00_admin/library.bib` | SETUP.md, крок 3 |
| Скрипти | `python3 90_pipeline/collect/state.py .` | показати помилку |

Мережеві налаштування Zotero й Obsidian перевірити неможливо — лише нагадати у звіті.

### 7. Git

- Якщо `.git` немає (шаблон завантажено архівом) — `git init`, `git add -A`, перший коміт `Initialize research vault from template` за правилами скіла `vault-git` (зокрема прибирання локів).
- Якщо є — один коміт `Configure vault for <topic_short>`. Push робить користувач, якщо сесія хмарна.

### 8. Звіт

1. **Заповнено** — список файлів, по рядку на кожен.
2. **Чекає на вас** — нумеровано, не більше 5 пунктів, найважливіше першим. Завжди містить: погодити RQ у `protocol.md`; вставити `PROJECT_PROMPT.md` в інструкції Claude Project; порожні поля config.
3. **Перший робочий крок** — одна дія: «Скажіть "збери джерела по RQ1"» (запускає `litnote-collect`).

## Чого не робити

- Не редагувати `CLAUDE.md`, `skills/` чи скрипти під конкретну роботу.
- Не ставити протоколу версію 1.0 без погодження автора.
- Не вигадувати вимоги кафедри чи журналу, номери розділів, дедлайни чи шляхи.
- Не починати збір джерел у цій самій сесії — після налаштування нова сесія дешевша.
- Не перезаписувати вже заповнені поля config без підтвердження.
